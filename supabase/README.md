# Общие аккаунты и демо-баланс

Приложение использует Supabase Auth и PostgreSQL. Аккаунты, ID игроков, состояние игры, демо-рубли и батлы скинов общие для всех устройств. Покупок и выплат за деньги нет.

## Первичная настройка

1. Создай проект Supabase.
2. В **SQL Editor** запусти весь файл [`schema.sql`](schema.sql). Затем запусти [`skin-battles.sql`](skin-battles.sql), [`community-features.sql`](community-features.sql), [`admin-inventory.sql`](admin-inventory.sql), [`cases.sql`](cases.sql), [`case-categories.sql`](case-categories.sql) и [`admin-moderation.sql`](admin-moderation.sql). Они добавят батлы, ленту апгрейдов, просмотр профилей, управление инвентарём, кейсы и категории кейсов, статусы игроков и отстранения. `cases.sql` создаёт публичное хранилище PNG, но разрешает загружать туда картинки только администраторам.
3. В **Authentication → Sign In / Providers → Email** отключи **Confirm email**. Приложение не собирает email: ник преобразуется в технический адрес вида `u-…@players.sgrader.invalid`. Поэтому восстановить забытый пароль нельзя; игрокам нужно использовать отдельный пароль для этой демо-игры.
4. В настройках Auth укажи Site URL `https://shroudesu.github.io/sgrader-upgrader-friends/`.
5. В **Project Settings → API** скопируй Project URL и публичный **publishable/anon key** в `supabase-config.js`. Не вставляй `service_role` key: он даёт полный доступ к базе.
6. Зарегистрируй игровой аккаунт с ником `shroud`. Затем в SQL Editor выполни [`promote_admin.sql`](promote_admin.sql). Выйди и войди снова — появится админ-панель.
7. Загрузи обновлённые файлы сайта в публичный репозиторий GitHub Pages и закоммить их. После сборки друзья смогут регистрироваться на общей базе.

Публичный ключ Supabase виден посетителям сайта по замыслу; доступ к данным ограничен RLS-политиками и серверными функциями из `schema.sql`. Роль администратора, операции с балансом и инвентарём проверяются в базе. Продажа предмета зачисляет полную стоимость без комиссии, удаление не начисляет баланс. Админское списание не позволяет опустить баланс ниже нуля и записывается в журнал транзакций.

В профиле игрок может сформировать демо-заявку с условным способом. Откроется Telegram-сообщение с ником и ID; пользователь отправляет его вручную, после чего администратор может начислить демо-рубли в админ-панели. Знак ₽ служит только оформлением интерфейса: форма не принимает оплату и не подтверждает платёж. Если игрок применил `SGRADER` при регистрации, к ручному начислению автоматически добавятся 10%.

Для батла создатель и гость ставят от одного до пяти скинов. Сумма ставки гостя должна быть не меньше 95% суммы ставки создателя; база проверяет это условие при вступлении. RPC `join_skin_battle` выбирает победителя с равной вероятностью и в той же транзакции передаёт ему весь банк. Клиентам разрешено только читать список батлов; создание, вступление и отмена проходят через серверные функции.

Администратор создаёт кейсы во вкладке **Админка**: выбирает скины из каталога, задаёт шанс каждого (суммарно 100%), цену и PNG-дизайн размером до 5 МБ. Игрок может открыть за раз от 1 до 10 кейсов. RPC `open_game_cases` списывает общую стоимость и сохраняет результаты как ожидающие награды; интерфейс позволяет забрать или продать каждый предмет отдельно либо обработать весь набор сразу. Продажа начисляет полную цену каждого предмета без комиссии. При обновлении сайта повторно запусти актуальный `cases.sql` в SQL Editor: миграция безопасно добавит таблицы и функции результатов. PNG публичен для показа в каталоге, а загружать и менять его могут только администраторы. Кейсы используют только игровой баланс.

Для уже настроенной базы, чтобы убрать комиссию игрока, в админском инвентаре, при обмене всего инвентаря и при продаже кейс-дропа, запусти [`remove-sale-commission.sql`](remove-sale-commission.sql) один раз. Файл заменяет только четыре функции продаж и не трогает данные игроков.

## Миграции для уже настроенной базы

- Запусти [`registration-starting-balance.sql`](registration-starting-balance.sql), чтобы новые регистрации начинались с 500 ₽. Балансы уже созданных аккаунтов не меняются.
- Запусти [`auth-upgrade-feed.sql`](auth-upgrade-feed.sql) после `community-features.sql`, чтобы гости видели ленту выигрышей до авторизации. Анонимный RPC выдаёт только карточки предметов, ник, аватар и ID игрока; UUID аккаунта не раскрывается.
- Если серверная комиссия продаж ещё не отключена, отдельно запусти [`remove-sale-commission.sql`](remove-sale-commission.sql).
- Для админских статусов онлайн/АФК/офлайн, очистки инвентаря, временного отстранения и лимита операций баланса до 1 млрд ₽ запусти [`admin-moderation.sql`](admin-moderation.sql). Миграция также включает события Realtime для профилей, балансов и инвентаря. Отстранение сохраняется в профиле, показывается сразу при изменении или при ближайшей проверке (раз в 5 секунд) и блокирует игровые изменения до срока окончания.

## Что хранится централизованно

- Supabase Auth хранит парольные хеши и сессии.
- `profiles` хранит игровой ник, общий ID, роль, применённый промокод и срок/причину отстранения.
- `wallets` хранит баланс демо-рублей; прямые изменения из браузера запрещены.
- `game_states` хранит игровой инвентарь и прогресс.
- `skin_battles` хранит открытые и завершённые батлы; список доступен авторизованным игрокам.
- `upgrade_wins` хранит выигранные предметы для общей ленты; открытые профили отдают только баланс, инвентарь, стоимость инвентаря и лучший дроп.
- `wallet_transactions` ведёт журнал игровых начислений и списаний.

Промокод `SGRADER` можно применить только при регистрации. Он даёт +10% к каждому ручному начислению демо-рублей администратором.
