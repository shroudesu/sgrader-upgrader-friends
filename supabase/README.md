# Общие аккаунты и демо-баланс

Приложение использует Supabase Auth и PostgreSQL. Аккаунты, ID игроков, состояние игры, демо-рубли и батлы скинов общие для всех устройств. Покупок и выплат за деньги нет.

## Первичная настройка

1. Создай проект Supabase.
2. В **SQL Editor** запусти весь файл [`schema.sql`](schema.sql). Для уже созданной базы запусти только миграцию [`skin-battles.sql`](skin-battles.sql), чтобы добавить таблицу и серверные функции батлов.
3. В **Authentication → Sign In / Providers → Email** отключи **Confirm email**. Приложение не собирает email: ник преобразуется в технический адрес вида `u-…@players.sgrader.invalid`. Поэтому восстановить забытый пароль нельзя; игрокам нужно использовать отдельный пароль для этой демо-игры.
4. В настройках Auth укажи Site URL `https://shroudesu.github.io/sgrader-upgrader-friends/`.
5. В **Project Settings → API** скопируй Project URL и публичный **publishable/anon key** в `supabase-config.js`. Не вставляй `service_role` key: он даёт полный доступ к базе.
6. Зарегистрируй на сайте игровой аккаунт с ником `shroud`. Затем в SQL Editor выполни [`promote_admin.sql`](promote_admin.sql). Выйди и войди снова — появится админ-панель.
7. Загрузи обновлённые файлы сайта в публичный репозиторий GitHub Pages и закоммить их. После сборки друзья смогут регистрироваться на общей базе.

Публичный ключ Supabase виден посетителям сайта по замыслу; доступ к данным ограничен RLS-политиками и серверными функциями из `schema.sql`. Роль администратора меняется только владельцем проекта в SQL Editor. Каждый вызов админского начисления проверяет эту роль в базе.

В профиле игрок может сформировать демо-заявку с условным способом. Откроется Telegram-сообщение с ником и ID; пользователь отправляет его вручную, после чего администратор начисляет демо-рубли в админ-панели. Знак ₽ служит только оформлением интерфейса: форма не принимает платежи и не подтверждает оплату. Если игрок применил `SGRADER` при регистрации, к ручному начислению автоматически добавятся 10%.

В батлах игрок блокирует один скин, соперник ставит свой. RPC `join_skin_battle` выбирает одну из двух сторон с вероятностью 50/50 и в той же транзакции переносит оба скина победителю. Клиентам разрешено только читать список батлов; создание, вступление и отмена проходят через проверяемые серверные функции.

## Что хранится централизованно

- Supabase Auth хранит парольные хеши и сессии.
- `profiles` хранит игровой ник, общий ID, роль и применённый промокод.
- `wallets` хранит баланс демо-рублей; прямые изменения из браузера запрещены.
- `game_states` хранит игровой инвентарь и прогресс.
- `skin_battles` хранит открытые и завершённые батлы; публичная выборка ограничена авторизованными игроками.
- `wallet_transactions` ведёт журнал игровых начислений и списаний.

Промокод `SGRADER` можно применить только при регистрации. Он даёт +10% к каждому ручному начислению демо-рублей администратором.
