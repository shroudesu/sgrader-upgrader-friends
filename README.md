# SGRADER UP

Статическая игра с общей авторизацией, профилями игроков, апгрейдом с несколькими скинами в ставке и общими батлами на Supabase. Каталог охватывает оружейные скины, ножи, перчатки, стикеры, агентов, граффити и музыкальные наборы из игрового источника CS2. Оружейные finish-варианты перечислены отдельно по износу, StatTrak и Souvenir. Числа по категориям и дата обновления находятся в [`catalog-source.json`](catalog-source.json).

Данные предметов берутся из публичного [CS2Cap/CS2-API](https://github.com/CS2Cap/CS2-API), собранного из файлов CS2; свежесть видна в `catalog-source.json`. Его лицензия приложена в [`CS2-API-LICENSE.txt`](CS2-API-LICENSE.txt). Для обновления файлов из корня проекта запусти `./refresh-cs2-catalog.ps1`; скрипт обновляет JSON, сжатые копии каталога и снимок источника в корне сайта, `deploy-site/` и `github-publish/`. Каталог показывает игровые превью, качество/износ, редкость, эффекты и год выпуска.

Цены каталога берутся из публичного [прайс-листа Market.CSGO](https://market.csgo.com/api/v2/prices/RUB.json): выбирается минимальное доступное предложение по точному `market_hash_name`. GitHub Actions обновляет компактный снимок примерно раз в 15 минут, а страница читает его с домена сайта и кэширует в браузере на 5 минут. Ручные цены для редких предметов хранятся в [`market-price-overrides.json`](market-price-overrides.json) в RUB и сохраняются при автоматических обновлениях. Аномальные котировки граффити выше 10 млн ₽ ограничиваются 400 тыс. ₽. Интерфейс показывает время снимка и долю каталога с найденной ценой. Если для предмета нет предложения или обновление фида недоступно, используется прежняя расчётная оценка; она помечена янтарным цветом и подсказкой. Покупки и новые кейсовые призы берут цену из текущего каталога. У уже существующих предметов инвентаря цена обновляется при входе и обновлении фида, затем сохраняется в профиле. Цены кейсов, заданные администратором, остаются настройкой кейса; позиции в уже созданных кейсах и незабранные кейсовые награды сохраняют цену на момент настройки/выпадения.

Фид содержит лучшие текущие предложения по названию предмета, а не данные каждого уникального лота: индивидуальные float, наклейки, seed паттерна и редкие особенности конкретного экземпляра не оцениваются отдельно. Поэтому цена фазы/паттерна может отличаться от цены уникального лота на площадке.

Список покрывает модели и варианты, опубликованные источником данных игры. Уникальные параметры конкретных торговых лотов (seed паттерна, фактический float, нанесённые стикеры и актуальная цена) не являются отдельными моделями в этом источнике и не импортируются.

В батлах каждый участник может поставить от одного до пяти скинов. Суммарная ставка гостя должна быть не меньше 95% суммарной ставки создателя; условие и равный шанс 50/50 проверяет база. После обновления фронтенда нужно повторно выполнить [`supabase/skin-battles.sql`](supabase/skin-battles.sql) в SQL Editor проекта Supabase, чтобы включить новый RPC для наборов скинов. Управление инвентарём игрока из админ-панели и пакетный обмен всего инвентаря требуют выполнить актуальную версию [`supabase/admin-inventory.sql`](supabase/admin-inventory.sql) в SQL Editor. Инструкция подключения базы находится в [`supabase/README.md`](supabase/README.md), схема — в [`supabase/schema.sql`](supabase/schema.sql).

Кейсы создаются в админ-панели: можно задать цену, PNG-оформление и шансы скинов (в сумме ровно 100%). Из каталога кейс открывается отдельной подвкладкой с сеткой предметов, ценами и шансами, отсортированными от наименьшего шанса. Открывать можно от 1 до 10 кейсов через выпадающий список; прокрутку можно пропустить в любой момент. Анимация длится 15 секунд и быстрее завершает замедление; до остановки имя, стоимость и подсветка результата скрыты. Кнопки получения и продажи плавно появляются после прокрутки. После открытия можно забирать скины по одному/все сразу или продавать по одному/все сразу; накопленные награды из всех открытий также обрабатываются двумя кнопками. Продажа начисляет полную стоимость без комиссии. Результаты скрываются сразу после обработки последней награды, а новые дропы кейсов попадают в общую live-ленту выигрышей с названием кейса. Шапка показывает число посетителей онлайн через Supabase Realtime Presence.

Чтобы администратор мог создавать категории кейсов, менять их порядок и переставлять кейсы внутри категорий, выполни актуальный [`supabase/case-categories.sql`](supabase/case-categories.sql) в Supabase SQL Editor после `supabase/cases.sql`. Если предыдущая версия миграции категорий уже была применена, запусти обновлённую ещё раз: она добавит сохранённый порядок.

Апгрейдер сохраняет результат на сервере до начала анимации, поэтому обновление страницы продолжает тот же прокрут без повторного розыгрыша. При ставке выше 50 000 ₽ и обычном шансе от 10% до 95% добавляется золотая отметка 5% по центру снизу поверх прежней дуги обычного шанса; она плавно появляется после старта прокрута. Золотая цепочка начинает расчёт с цены выбранной обычной цели (например, цель ₽1 000 000 ведёт к этапу ₽2 000 000). Если подходящего скина выше лимита каталога ₽8 888 888 уже нет, следующие множители продолжают прокрут за денежный приз и зачисляют его на денежный баланс. Бонус даёт пять последовательных удвоений цены (x2, x4, x8, x16, x32) с шансами 50%, 45%, 40%, 35% и 15%. Первый этап гарантирует x2-цель даже при промахе; последующие промахи оставляют последний успешно полученный скин или денежный приз. Для этого запускай [`supabase/upgrade-bonus.sql`](supabase/upgrade-bonus.sql) после `schema.sql` и `community-features.sql`. Если миграцию уже запускали, повторно выполни актуальный файл, чтобы заменить функции; данные игроков сохраняются.

Новые аккаунты начинают с 500 ₽. Для существующей базы один раз выполни [`supabase/registration-starting-balance.sql`](supabase/registration-starting-balance.sql): изменится только стартовый баланс будущих регистраций. Чтобы лента выигрышей показывалась до входа, выполни [`supabase/auth-upgrade-feed.sql`](supabase/auth-upgrade-feed.sql). Для серверной продажи без комиссии существующей базой также требуется [`supabase/remove-sale-commission.sql`](supabase/remove-sale-commission.sql). Полные схемы [`supabase/schema.sql`](supabase/schema.sql) и [`supabase/community-features.sql`](supabase/community-features.sql) включают соответствующие изменения для новых установок.

Баланс отображается в выбранной валюте RUB/USD; конвертация в интерфейсе использует фиксированное соотношение 1 USD = 90 RUB. Пополнение открывает заготовленное сообщение администратору и само по себе не проводит платёж. Администратор может начислять и снимать баланс; списание не может опустить его ниже нуля. Исход батла выбирается сервером с шансом 50/50.

Не загружайте в `supabase-config.js` ключ `service_role`. Нужен только публичный publishable/anon key, защищённый RLS-политиками из SQL-схемы.
